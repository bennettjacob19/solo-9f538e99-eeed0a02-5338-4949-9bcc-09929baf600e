# 虚拟卷在线换条带模拟（Flask + SQLite）

模拟一块由两块物理盘（每盘 16 槽、每槽 4 KiB）组成的 32 块虚拟卷，在**不停止读写**的
前提下把条带从“单块交替”改成“每 2 块 / 每 4 块换盘”。搬运逐批提交，支持在写槽后、
提交前让进程退出，重启后从最后一个已提交位置继续。另提供值班员**试写轮次**：先试写、
核对，再整轮确认或撤销。

## 模型与规则

| 项目 | 实现 |
| --- | --- |
| 物理盘 | SQLite 表 `slots`：盘 0/1，各 16 槽，共 32 个数据槽，初始全部装满 4 KiB 块 |
| 初始条带 | 单块交替：LBN `l` 落在盘 `l%2`、槽 `l//2` |
| 新条带 | 选 `k=2` 或 `k=4`：LBN `l` 落在盘 `(l//k)%2`、槽 `(l//(2k))*k + l%k` |
| 临时槽 | 独立表 `staging`，同一时刻最多 1 块正文（题目要求的额外暂存上限） |
| 每批额度 | 表单填写“本批最多写几次盘槽正文”，**临时槽 stage/unstage 也计次**；额度 1 也执行一次搬运，必然推进 |
| 在线读写 | 任意阶段按 LBN 读写；块在临时槽时读/写都落到 `staging`，始终拿到最近一次已提交正文 |
| 值班员改写 | 独立事务立即提交，不占用搬运批次额度；正文随块一起搬到目标槽 |
| 崩溃恢复 | 每批是一个 SQLite 事务（rollback journal + `synchronous=FULL`）；提交前 `os._exit(77)`，重启后 journal 自动回滚，已提交批次保留 |

### 搬运算法：位置置换的环分解 + 单临时槽

换条带本质是 32 个盘位之间的一个置换。规划器**按当前盘位**（不假设永远是初始布局，
因此可连续再次换条带）把置换分解成若干环，每个非平凡环：

1. `stage`：环起点的块写入临时槽，起点腾出“洞”；
2. 沿环反向逐条 `move`：把块写进洞，洞移动到该块原来的槽；
3. `unstage`：临时槽里的块写进最后一个洞。

每个环只暂存一块，所有操作都计入批次写入次数。

## 试写轮次（先试写、核对，再整轮确认 / 撤销）

### 实现：就地写 + 撤销字节日志

试写补丁**就地**打到块的当前正文上（块在盘槽就写 `slots`，在临时槽就写 `staging`），
所以原读入口立刻读到新值、换条带照常搬运；另存的数据只有每个试写位置在**首次试写前**
的 1 个原始字节（表 `trial_bytes`，主键 `(lbn, offset)`），试写值本身不另存。

| 规则 | 落地方式 |
| --- | --- |
| 每次只开一轮 | 单行表 `trial_round`；存在未结束轮次时拒绝再开，只能确认/撤销收尾 |
| 按 LBN + 字节偏移提交 hex 补丁 | 补丁项 `{offset, hex}`，可多字节、可一次多项；同一笔内后写覆盖先写 |
| 提交后原入口立即读到新值 | 就地更新正文，一个事务立即提交；块在临时槽时写 `staging`，照常换条带 |
| 一轮 4096 个可撤销字节位置 | 计数 = `trial_bytes` 去重行数；同位置反复试写只占一行（只算一次） |
| 超额整笔拒绝 | 先计算本笔将新增的去重位置，超 4096 直接抛错回滚，一个字节都不落 |
| 另存试写/还原数据 ≤ 4 KiB | 另存载荷 = 去重位置数 × 1 字节，恒 ≤ 4096 字节（表结构等元数据不计入载荷） |
| 整块改写使旧试写失效并腾额度 | `PUT /api/blocks/<lbn>` 成功后在同一事务删除该块全部撤销行；再试写时从新正文捕获撤销字节，故撤销恢复到整块改写后的正文 |
| 确认/撤销只动仍有试写的块、每块正文最多写一次 | 按 `DISTINCT lbn` 遍历；确认零正文写（试写值本就在正文里），撤销每块合并成一次正文写 |
| 网页显示实际写几次盘槽/临时槽正文 | 收尾返回并持久化 `disk_slot_writes` / `staging_writes`（表 `trial_last`，重启后仍显示） |
| 收尾失败整轮保持原状 | 收尾是单个事务，异常即 ROLLBACK；轮次、撤销日志、正文全部不变 |
| 重启后续写/确认/撤销 | 轮次与撤销日志都是已提交状态；进程退出后重开页面仍能继续补丁或收尾 |

### 与换条带的相互作用

试写就地落在正文里，搬运 `stage/move/unstage` 直接带着试写字节走，无需特殊处理。
临时槽里的块同样可以试写或整块改写；整块改写成功即作废旧试写。换条带的“提交前崩溃”
回滚只影响未提交的搬运批次，已提交的试写轮次不受影响。

## 启动

### Docker Compose（推荐）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

SQLite 数据文件放在命名卷 `volume-data`（容器内 `/data/volume.db`），容器重启后
已提交状态保留。

### 本地 Python

```bash
pip install -r requirements.txt
python -m flask --app app.server run --host 0.0.0.0 --port 8000 \
    --without-threads --no-reload --no-debugger
```

数据库路径由环境变量 `VIRTUAL_VOLUME_DB` 覆盖，默认 `data/volume.db`。
注意必须带 `--no-reload`，否则模拟崩溃时 reloader 监控进程会重新拉起服务。

## 网页操作

- **开始换条带**：选择每 2 块或每 4 块换盘，生成搬运计划。
- **执行一批并提交**：填写本批最大写入次数（含临时槽）；勾选“写槽后、提交前退出”
  会让进程以退出码 77 退出，页面自动轮询等待重启后刷新。
- **在线读 / 整块改写**：输入 LBN（0..31）；改写正文不足 4 KiB 自动补零、超长截断，
  立即提交。块在临时槽时同样可读写。整块改写成功会作废该块此前的试写并腾出额度。
- **试写轮次**：点“开启一轮试写”后，按 LBN 与补丁文本（每行 `字节偏移:十六进制`，
  如 `0:deadbeef`）提交；卡片实时显示可撤销位置 `n/4096`、另存载荷 `n/4096 字节`、
  有试写的块；最后“整轮确认”（零正文写）或“整轮撤销”（每块最多一次正文写），
  并显示最近一次收尾实际写了几次盘槽/临时槽正文。
- 页面展示：迁移状态卡（进度、本批写入次数、临时槽占用、校验结果）、试写轮次卡、
  两块盘 16 槽位图（含每槽目标 LBN、空洞、暂存标记）、32 个逻辑块的当前盘位/目标盘位/
  试写位置数明细表、最近 25 条事件日志。

## HTTP API（测试/脚本用）

| 方法与路径 | 说明 |
| --- | --- |
| `GET /api/snapshot` | 全量状态（块位置、临时槽、迁移进度、试写轮次、事件、校验） |
| `POST /api/migration/start` `{"stripe_k":2\|4}` | 开始换条带 |
| `POST /api/migration/batch` `{"budget":N,"crash":bool}` | 执行一批；`crash=true` 时提交前退出 |
| `GET /api/blocks/<lbn>` | 按 LBN 读（自动识别临时槽），返回 hex 正文 |
| `PUT /api/blocks/<lbn>` `{"body_hex":...}` 或 `{"body":"..."}` | 按 LBN 整块改写，必须正好 4096 字节；成功后作废旧试写 |
| `GET /api/trial` | 试写轮次状态（进行中的轮次 + 最近一次收尾统计） |
| `POST /api/trial/open` | 开启唯一一轮试写（已有未结束轮次时 400） |
| `POST /api/trial/patch` `{"lbn":N,"patches":[{"offset":O,"hex":".."}]}` | 提交一笔试写；超额/非法整笔拒绝（400，轮次不变） |
| `POST /api/trial/finalize` `{"confirm":true\|false}` | `true` 确认（0 正文写）；`false` 撤销（每块至多 1 次正文写），返回盘槽/临时槽实写次数 |
| `GET /api/verify` | 校验：32 槽齐全、正文 4 KiB、临时槽 ≤1、完成后盘位符合新条带、试写计数/载荷/引用一致 |

试写测试自动起停 Flask 子进程，覆盖：单轮约束与重复开启拒绝、补丁后原入口即时读到
新值（含临时槽块）、同位置反复试写只算一次、4096 额度边界与第 4097 个位置整笔拒绝、
非法 hex/越界/跨块尾/空补丁整笔拒绝、另存载荷 ≤4 KiB、整块改写作废旧试写并腾额度、
再试写后撤销恢复到改写后正文、多块撤销每块恰好一次正文写且盘槽/临时槽计数正确、
试写字节随换条带搬到目标槽、进程重启后续写/确认/撤销、搬运崩溃回滚后轮次仍一致、
收尾失败（注入写故障）整轮原状保留、校验不变量与重置清理。当前结果：**310 项检查全部
通过（219 + 91）**。

### 实测记录（真机 HTTP 核对）

在临时库上起真实 Flask 服务按规则逐档核对，关键观测：

1. 盘槽块补丁后 `GET /api/blocks/0` 首字节立即变为 `cafe..`；
2. 换条带 `budget=1` 后 LBN2 进入临时槽，对其试写 `5aa5..`，经临时槽入口读到新值；
3. 对暂存块整块改写返回 `trial_positions_invalidated=3`，轮次额度同步释放；
4. 再试写 1 字节后把该块搬下临时槽，正文随块到盘槽（首 3 字节 `4f 7e 45`）；
5. 撤销只处理仍有试写的 2 个块、盘槽正文各写 1 次、临时槽 0 次，且恢复到整块改写后的
   正文（`OVE..`）而非最初正文；
6. 一笔填满 4096 位置（另存正好 4096 字节）后，第 4097 个位置整笔拒绝、目标块一字节
   未动；确认返回正文写 0 次；
7. `kill` 重启后未结束轮次、额度与试写字节均在，可继续补丁并成功撤销；`/api/verify`
   全程 `ok`。

## 已知限制 / 未做项

- 未在本机实际执行 `docker compose build`（当前环境没有 docker 二进制），仅校验了
  compose 文件与 Dockerfile 的关键指令；镜像基于官方 `python:3.11-slim`，命令与本地
  验证一致，数据落在命名卷 `volume-data`（容器内 `/data/volume.db`）。
- 使用 Flask 内置开发服务器（单线程），未上 gunicorn/uvicorn 等生产 WSGI；单线程也让
  试写/收尾与模拟崩溃的行为确定可复现。
- 正文为模拟数据（初始块头 + 零填充），未模拟真实磁盘延迟、校验和或冗余副本。
- “另存 ≤4 KiB”只约束试写/还原的**数据载荷**（每个去重位置 1 个撤销字节）；表结构、
  索引与事件日志属于系统元数据，不在该口径内。
- 试写轮次与换条带可并行存在，但同一时刻只允许一轮试写；没有多值班员并发试写的隔离
  机制（单线程服务器串行处理请求）。
